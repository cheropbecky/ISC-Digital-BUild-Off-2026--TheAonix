Question 1 — Functional dependencies

For ENROLMENT(StudentNo, UnitCode, StudentName, UnitTitle, Grade), assume a student has one name, a unit code determines one unit title, and each student receives one grade per unit. Identify a candidate key and explain whether the relation is in 2NF.

Solution: The candidate key is (StudentNo, UnitCode). Both key attributes are required to identify a grade. StudentName depends only on StudentNo, and UnitTitle depends only on UnitCode; these are partial dependencies on a proper subset of the composite key. The relation is not in 2NF. Decompose to STUDENT(StudentNo, StudentName), UNIT(UnitCode, UnitTitle), and ENROLMENT(StudentNo, UnitCode, Grade).

Question 2 — Join and grouping

Return unit codes with at least two enrolled students. Given ENROLMENT(StudentNo, UnitCode, Grade), write a query that omits units with fewer than two rows.

SELECT UnitCode, COUNT(DISTINCT StudentNo) AS student_count
FROM ENROLMENT
GROUP BY UnitCode
HAVING COUNT(DISTINCT StudentNo) >= 2;

Why HAVING? WHERE filters rows before grouping; HAVING filters groups after aggregate values are computed.

Question 3 — Index choice

A table contains several million registrations. Most queries filter by UnitCode and then order by RegisteredAt. Suggest a composite B-tree index and state one cost.

Solution: Consider (UnitCode, RegisteredAt) when predicates constrain the leading column and the ordering matches the second column. The index can reduce examined rows and avoid a sort, but it consumes storage and adds write work when either indexed value changes. Validate with the database's actual execution plan and representative data.

Question 4 — Transactions

Explain a lost update and name an isolation mechanism that can prevent it. A lost update occurs when concurrent transactions read the same old value and the later write overwrites the earlier update. Row locking or serializable isolation can prevent this, with different concurrency costs.

Quick review

  • State the functional dependencies before decomposing a relation.
  • Check decomposition for lossless joins and dependency preservation.
  • Read estimated rows, actual rows, and scan type in an execution plan.
  • Discuss atomicity, consistency, isolation, and durability in transaction scenarios.
