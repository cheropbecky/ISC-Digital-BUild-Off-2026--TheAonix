Compiler Design: Working Notes

Lexing · Parsing · Semantic Analysis

These notes follow a source program from characters to an intermediate representation. The examples are deliberately small: trace each transformation by hand before relying on a parser generator.

1. Compiler pipeline

  1. Lexical analysis: groups characters into tokens and records source locations. Whitespace is usually discarded except where it separates tokens.
  2. Parsing: checks token order against a grammar and builds a concrete or abstract syntax tree.
  3. Semantic analysis: resolves names, checks types and scope, and annotates the tree with meaning.
  4. Intermediate representation: lowers language constructs to a form suitable for optimization and target-code generation.

2. Tokens and regular expressions

A token is a category plus an optional lexeme and source span. For a simple identifier, a useful pattern is [A-Za-z_][A-Za-z0-9_]*. Apply longest-match (maximal munch): when multiple rules match at the current position, choose the longest lexeme, then use rule priority to break ties.

sum = value + 12;
IDENT(sum)  ASSIGN(=)  IDENT(value)  PLUS(+)  INTEGER(12)  SEMICOLON(;)

3. LL(1) predictive parsing

For a grammar to be LL(1), a parser must choose one production using one lookahead token. Left recursion prevents direct recursive descent; left factoring exposes a shared prefix.

Expr  → Term ExprTail
ExprTail → + Term ExprTail | ε
Term  → Factor TermTail
TermTail → * Factor TermTail | ε
Factor → ( Expr ) | id

Compute FIRST sets from terminals at the beginning of derivations. Compute FOLLOW sets from what can legally appear after a nonterminal. For an ε production, its table entries are selected using FOLLOW(lhs). A multiply expression binds more tightly here because multiplication is handled inside Term.

4. Shift-reduce parsing

Bottom-up parsers shift input symbols onto a stack and reduce a recognized handle to its production's left-hand side. A shift/reduce conflict asks whether to consume another token or reduce now; precedence and associativity declarations resolve common arithmetic conflicts.

5. Three-address code

total = price * quantity + tax
t1 = price * quantity
t2 = t1 + tax
total = t2

Temporary names make evaluation order explicit. A basic block has one entry and no branches except at its end, which helps local data-flow analysis and optimization.

Revision checklist

  • Trace tokenization including a malformed character and its source position.
  • Eliminate left recursion, then verify FIRST/FOLLOW table conflicts.
  • Draw a parse tree and its abstract syntax tree for the same expression.
  • Translate nested expressions to three-address code and identify basic blocks.
